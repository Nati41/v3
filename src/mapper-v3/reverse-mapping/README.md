# מצב ניסיוני - Reverse Mapping

## מה התיקייה הזו עושה?
מממשת **מצב מיפוי הפוך** (ניסיוני):
במקום לבחור שדה מתבנית ולמפות אותו - המשתמש מצייר אלמנטים פיזיים על ה-PDF,
ואז AI מזהה מה כל אלמנט.

## באילו כלים היא משתתפת?
**Mapper v3** - כמצב עבודה חלופי.

## מי קורא לה?
- `DrawController.js` - חותך את הזרימה הרגילה ושולח `REVERSE_DRAW_COMPLETE`
- `mapper-v3.html` - כפתור "מצב ניסיוני" מפעיל/מכבה

## מתי היא פעילה?
רק כשהמשתמש מפעיל את מצב ניסיוני (toggle). **מנותקת לחלוטין** מהמיפוי הרגיל.

## קבצים מרכזיים

| קובץ | תפקיד |
|------|--------|
| `ReverseMappingMode.js` | **בקר ראשי** - הפעלה/כיבוי, ניהול אלמנטים, שילוב AI. חושף `window.ReverseMappingMode` ל-DrawController |
| `ReverseMappingOverlay.js` | **תגיות ויזואליות** - תג `[מספר | סוג]` על כל אלמנט. סוגים: F=שדה, C=צ'קבוקס, R=רדיו, T=טבלה, S=חתימה |
| `ReverseMappingPanel.js` | **פאנל ולידציה** - הצגת תוצאות AI לאישור המשתמש |
| `ReverseMappingAI.js` | **שירות AI** - שולח תמונה עם תגיות ל-Claude, מקבל זיהוי סמנטי |
| `reverse-mapping.css` | **עיצוב** - סגנונות לתגיות, פאנל, כלים |

## זרימת עבודה
```
הפעלת מצב ניסיוני → כלי ציור בסרגל צד → ציור על PDF →
DrawController חותך (REVERSE_DRAW_COMPLETE) → ReverseMappingMode שומר →
תגית [1|F] מופיעה → ... → "זהה שדות" → AI מזהה → פאנל אישור
```

## עיקרון ארכיטקטוני חשוב
> ה-DrawController בודק אם מצב ניסיוני פעיל (`window.ReverseMappingMode.isActive()`).
> אם כן - הוא פולט אירוע `REVERSE_DRAW_COMPLETE` עם ה-bbox הגולמי **ולא יוצר שדה בכלל**.
> זה מבטיח שאין התנגשות עם הזרימה הרגילה ושהקואורדינטות מדויקות.
